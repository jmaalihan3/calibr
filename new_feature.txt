Implement a persistent user statistics, allowing users to monitor assessment performance and metacognitive calibration over time.
## Dashboard Statistics

Display five cumulative statistics across all completed assessments:

1. **Brier Score:** Mean squared difference between confidence (0–1) and correctness (0 or 1). Lower is better.
2. **Calibration Bias:** Average confidence minus answer accuracy, expressed in percentage points. Positive indicates overconfidence; negative indicates underconfidence.
3. **Answer Accuracy:** Percentage of correctly answered questions.
4. **Average Confidence:** Mean reported confidence (0–100%).
5. **Assessments Completed:** Total number of completed assessments.

Calculate cumulative metrics using all valid question-level responses, weighted equally by question rather than averaging assessment-level metrics.

## 3. Longitudinal Tracking

Implement historical charts showing statistics across completed assessments.

- **Calibration:** Brier score and calibration bias.
- **Performance:** Answer accuracy and average confidence.
- Use assessment completion dates or chronological assessment numbers on the horizontal axis.
- Clearly label axes, units, and metrics.
- Provide a simple way to switch between calibration and performance charts.

## 4. Assessment History

Display a chronological table of completed assessments, showing:

- Assessment name and completion date
- Answer accuracy
- Average confidence
- Brier score
- Calibration bias

Each assessment should link to its existing results page, including question-level feedback.

Display the most recent assessments first.

## 5. Persistence and Backend

Inspect the existing database schema and assessment submission workflow before modifying anything.

- Reuse existing persisted assessment and question-response data wherever possible.
- Ensure completed assessments retain their question-level correctness, confidence ratings, identifiers, and completion timestamps.
- Associate records with the existing user or participant identifier.
- Create or modify database tables only where necessary.
- Implement REST API endpoints for cumulative statistics, historical trends, and assessment history.
- Exclude incomplete assessments from statistics.
- Avoid double-counting submissions or attempts.
- Preserve compatibility with both SQLite and PostgreSQL.

Derive aggregate statistics from persisted question-level data. Avoid storing redundant cumulative statistics unless necessary for performance.

## 6. Frontend Design

Create a dedicated **My Statistics** dashboard accessible from the existing application navigation.

Organize it into three sections:

1. **Overview:** Five summary statistics displayed in compact cards.
2. **Performance History:** Interactive or switchable charts showing longitudinal trends.
3. **Assessment History:** Chronological table with links to individual results.

Include concise explanations of Brier score and calibration bias, using tooltips or short descriptions.

Handle users with no completed assessments gracefully.

## 7. Testing and Validation

Add tests verifying:

- Correct Brier score, bias, accuracy, and average confidence calculations.
- Correct aggregation across assessments with different numbers of questions.
- Correct handling of incomplete assessments and missing or invalid data.
- Correct chronological ordering.
- Correct persistence across application restarts.
- No duplicate counting of completed assessment submissions.
- Compatibility with SQLite and PostgreSQL.

## 8. Implementation Constraints

- Do not modify existing assessment behavior or feedback unnecessarily.
- Preserve existing data and functionality.
- Prefer minimal, maintainable changes.
